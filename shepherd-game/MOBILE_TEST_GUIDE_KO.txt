Protect the Flock v2.3.9 모바일 상태판·카메라 관성·발열·성능·조작 시험 안내
===================================================

1. 광고 회사 계정이 없어도 시험할 수 있습니다
-------------------------------------------------
- 이 버전의 GameDistribution gameId는 비어 있습니다.
- 일반 실행에서는 외부 광고 SDK를 내려받지 않으며 실제 광고도 전혀 나오지 않습니다.
- 모바일 조작, 가로 화면, 그래픽, 저장과 불러오기는 광고 연결과 무관하게 작동합니다.

2. 일반 모바일 시험
-------------------
- ZIP을 풀어 웹 서버에 올린 뒤 휴대폰 또는 태블릿 브라우저에서 여십시오.
- 한국어 바로 열기: index.html?lang=ko
- 영어 바로 열기: index.html?lang=en
- 히브리어 바로 열기: index.html?lang=he
- ZIP 파일이나 index.html을 휴대폰 파일 앱에서 직접 여는 방식은 브라우저 보안 때문에 3D 모듈이 실행되지 않을 수 있습니다. 반드시 http:// 또는 https:// 주소로 시험하십시오.

3. 광고 연결 위치만 시험하는 방법
----------------------------------
- 실제 광고 대신 내부 시험 화면을 사용하려면 주소 끝에 adtest=1을 붙이십시오.
- 예: index.html?lang=ko&adtest=1
- 내부 시험 화면은 약 2.2초간 표시되며 광고가 아닙니다.
- 표시되는 동안 게임·입력·소리가 멈추고, 사라진 뒤 다시 시작되는지를 확인할 수 있습니다.

시험 위치 A — 저장한 게임 다시 열기
1) 새 게임을 시작합니다.
2) 왼쪽 위 일시정지 버튼을 누르고 저장합니다.
3) 페이지를 새로 연 뒤 이어하기를 누릅니다.
4) 내부 광고 시험 화면이 끝난 다음 저장 위치에서 이어지는지 확인합니다.

시험 위치 B — 야영지 임무 성공
1) adtest=1 상태에서 야영지 임무를 성공합니다.
2) 성공 연출 뒤 내부 광고 시험 화면이 표시되는지 확인합니다.
3) 시험 모드에서는 이 위치를 쉽게 확인하도록 항상 표시됩니다.
4) 나중에 실제 광고가 연결되면 모바일에서만 성공 시 33% 확률로 요청합니다.

4. 가로 화면 확인
-----------------
- Android·일부 태블릿 브라우저에서는 전체 화면과 가로 잠금을 자동으로 요청합니다.
- iPhone/iPad Safari처럼 브라우저가 자동 회전 잠금을 허용하지 않는 경우에는 세로 화면에서 게임을 차단하고 가로로 돌리라는 안내를 표시합니다.
- 가로로 돌린 뒤 게임 화면과 조작 버튼이 나타나는지 확인하십시오.
- 일반 Chrome 탭 또는 사이트 미리보기 창에서는 게임을 누르기 전 브라우저 상단 막대가 남을 수 있습니다. v2.3.9는 이 막대를 제외한 실제 남은 높이를 측정해 시작 화면을 자동으로 가로형 2열로 바꿉니다.
- 휴대기기에서 첫 화면을 처음 터치하는 순간, 그리고 언어 선택·새 게임·이어하기·캐릭터 시작을 누를 때마다 전체 화면과 가로 잠금을 요청합니다. 브라우저 정책이나 기기의 회전 잠금 때문에 요청이 거부되어도 모든 시작 버튼과 캐릭터 선택 버튼은 짧은 가로 화면 안에 유지됩니다.
- 홈 화면에 설치한 앱으로 열면 처음부터 주소창 없는 전체 화면으로 실행됩니다.

5. 모바일 조작 확인
-------------------
- 왼쪽 아래 원형 조이스틱: 방향과 속도를 연속적으로 조절
- 모바일 시점: 다비드의 이동 방향을 높은 원거리 시점에서 자동 추적(화면 드래그 시점 조작 없음)
- 오른쪽 아래 큰 버튼: 항상 돌팔매 전용. 길게 눌러 충전하고 손을 떼어 발사
- 공격 버튼 위의 지팡이 그림 버튼: 한 번 누르면 즉시 지팡이 공격 또는 양 떼 재촉
- 지팡이 버튼에는 한국어·히브리어·영어 표시 글씨가 전혀 없어야 합니다.
- 물매 공격 버튼을 누르는 동안 시야가 다비드 뒤의 가까운 집중 시점으로 들어가고, 손을 떼면 기존 높은 원거리 시점으로 돌아오는지 확인하십시오.
- 그 왼쪽 위부터: 돌 줍기 → 달리기 → 양떼 부르기
- 양떼 부르기는 짧게 한 번만 눌러도 멀리 있는 양들이 다비드에게 달려와야 합니다.
- 왼쪽 위 석판 버튼: 일시정지
- 일시정지 메뉴: 언어, 소리, 계속, 저장, 게임 종료
- 모바일에는 마우스 감도 항목이 표시되지 않습니다.

6. 저장 확인
------------
- 진행 상태는 localStorage 기본 저장과 IndexedDB 보조 저장에 함께 기록됩니다.
- 저장 후 페이지를 닫았다 다시 열고 이어하기가 활성화되는지 확인하십시오.
- 시크릿/비공개 모드는 브라우저가 사이트 데이터를 지울 수 있으므로 장기 저장 시험에는 사용하지 않는 편이 좋습니다.

7. 홈 화면 앱 설치 확인
-----------------------
- 앱 설치 배너와 홈 화면 아이콘은 반드시 https:// 주소 또는 개발용 localhost 주소에서 시험하십시오.
- 파일 앱에서 index.html을 직접 열거나 일반 http:// 공개 주소로 열면 브라우저 보안상 앱 설치 기능이 작동하지 않습니다.
- 언어를 고른 뒤 시작 화면에서 전용 아이콘이 있는 설치 배너가 나타나는지 확인하십시오.
- Android Chrome: '앱으로 설치'를 누른 뒤 운영체제 설치 확인창에서 설치합니다.
- iPhone/iPad Safari: '앱으로 설치'를 누르고 표시되는 안내대로 공유 버튼 → 홈 화면에 추가를 선택합니다.
- 설치 후 홈 화면에 다비드와 양이 함께 있는 전용 아이콘이 표시되는지 확인하십시오.
- 홈 화면 아이콘으로 실행하면 브라우저 주소창 없이 전체 화면으로 열리고 가로 화면을 요청합니다.
- 홈 화면 아이콘으로 다시 열었을 때 설치 전 선택한 영어·한국어·히브리어 설정이 유지되는지 확인하십시오.
- 이미 설치한 앱으로 실행하거나 데스크톱으로 실행하면 설치 배너가 나오지 않습니다.
- '나중에'를 선택하면 7일 동안 배너를 다시 띄우지 않습니다.
- 시각 시험용 주소: index.html?lang=ko&installtest=1 (데스크톱에서도 배너 디자인 확인 가능)

8. 재실행 캐시 확인
-------------------
- 처음 접속한 뒤 게임에 실제로 사용된 모델·음원·이미지는 기기 캐시에 저장됩니다.
- 두 번째 실행부터 핵심 시작 파일과 사용한 자산을 재활용하여 로딩 중 불필요한 재다운로드를 줄입니다.
- 게임을 업데이트하면 v2.3.9 캐시 이름이 바뀌어 이전 핵심 파일과 섞이지 않도록 구성했습니다.
- 브라우저의 사이트 데이터나 앱 저장 공간을 지우면 캐시와 저장 게임이 함께 지워질 수 있으므로 주의하십시오.

9. 데스크톱 확인
---------------
- 데스크톱에서는 기존 키보드·마우스 조작만 표시됩니다.
- 게임 코드가 모바일 광고 요청을 데스크톱에서 즉시 건너뛰므로 두 위치 모두 광고가 나오지 않습니다.
- 데스크톱에서는 installtest=1을 붙이지 않는 한 앱 설치 배너가 표시되지 않습니다.

10. v2.3.9 상태판·카메라·발열·나무·성전·직접 동작 확인
-------------------
- 한국어에서 오른쪽 위 상태판의 체력·돌·존중·셰켈 네 줄이 석판 위·아래 경계를 넘지 않는지 확인하십시오.
- 상태판 체력 막대가 오른쪽으로 삐져나오지 않고, 글자와 막대가 같은 석판 안에서 정렬되는지 확인하십시오.
- 모바일 새 게임 시작 시 다비드, 양, 현재 1성전, 올리브나무와 대추야자나무를 로딩 화면 안에서 준비합니다.
- 시작 뒤 모든 동물·시민 모델을 연속 해석하던 백그라운드 작업은 제거했습니다. 선택형 인물과 동물은 실제 등장할 때만 준비됩니다.
- 멀리서 옛 임시 성전이 먼저 보이지 않고 현재 1성전만 표시되는지 확인하십시오.
- 올리브산과 야영지의 나무가 사라지거나 거대한 크기로 변하지 않고 정상 비율로 표시되는지 확인하십시오.
- 가까운 올리브나무는 현재 상세 모델, 먼 나무는 가벼운 윤곽으로 보이며 가까워질 때 자연스럽게 상세 모델로 전환됩니다.
- 가까운 다비드·양·기물은 선명하게 유지되고 먼 지형·도시·동물은 거리 안개 속에서 대비가 낮아지는지 확인하십시오.
- 모바일에서는 동일한 외형과 애니메이션을 유지한 경량 3D 모델을 자동 선택하고, 데스크톱에서는 기존 원본 모델을 그대로 사용합니다.
- 모바일 내부 렌더링은 고정 배율이 아니라 화면의 실제 CSS 픽셀 수에 대한 픽셀 예산으로 조절됩니다. 일반/중간부하/고부하 단계의 목표 백버퍼는 약 62만/47만/36만 픽셀이며, 초고해상도 화면에서만 최저 배율 0.42까지 허용합니다. 작은 화면에서는 최대 1.08 배율을 유지합니다.
- 모바일은 평상시 안정적인 30FPS를 목표로 합니다. 장면의 드로 콜·삼각형·프레임 작업이 지속적으로 높은 경우 가까운 장면을 보존한 채 먼 나무·도시·동물·돌의 상세 범위와 해상도를 먼저 줄입니다.
- 높은 부하가 계속 누적되는 경우에는 60Hz와 120Hz 화면에 일정하게 맞는 20FPS 지속 모드로 자동 전환해 전력과 발열을 낮춥니다. 부하가 충분히 내려가면 단계적으로 30FPS로 복귀합니다.
- 움직이는 3D 화면 뒤를 실시간으로 다시 샘플링하던 모바일 HUD와 조작 버튼의 배경 블러를 제거했습니다. 글자·석판·원형 버튼의 기본 외형은 유지됩니다.
- 렌더러의 드로 콜·삼각형·프레임 작업량을 더 보수적인 한도로 판단해 중간/고부하 단계에 더 일찍 진입합니다.
- 화면이 숨겨진 탭에서는 3D 게임 루프가 즉시 렌더링을 건너뜁니다.
- 모바일의 적 체력 UI는 10Hz, 성전 불꽃·연기·새 등 장식 갱신은 약 15Hz로 제한해 불필요한 DOM/CPU 작업을 줄였습니다.
- 모바일에서는 저전력 그래픽 장치를 우선 요청하고, 양 떼의 충돌·길찾기 계산을 3프레임 중 2프레임만 실행해 시간 보정하면서 발열 부하를 낮춥니다.
- 조이스틱 무반응 구간은 0.13이며, 손가락이 방향을 바꾸면 이동 방향에 즉시 반영되어야 합니다.
- 전·후·좌·우와 대각선을 빠르게 바꿔도 실제 이동 방향이 조이스틱 그림과 어긋나거나 반대로 튀지 않아야 합니다.
- 한 번 조이스틱을 누른 동안에는 시작 순간의 카메라 방향을 이동 기준으로 고정합니다. 카메라가 따라 도는 중 손가락이 미세하게 흔들려도 회전 목표가 다시 밀려나지 않는지 확인하십시오.
- 자동 추적 카메라는 이동 입력보다 의도적으로 느리게 따라옵니다. 최대 회전 속도는 성 밖 약 2.35rad/s, 성 안 약 1.85rad/s이며 반대 방향으로 휙 넘어가지 않는지 확인하십시오.
- 돌팔매 버튼을 누르는 동안 시야 거리·높이·화각이 집중 모드로 좁아지고 조준점이 보이는지 확인하십시오.
- 집중 모드에서도 조이스틱 방향, 다비드 이동, 시야 회전이 같은 방향으로 반응하는지 확인하십시오.
- 지팡이 그림 버튼을 누르면 선택 메뉴나 별도 전환 없이 즉시 지팡이 동작이 나오는지 확인하십시오.
- 큰 자산의 캐시 저장은 게임으로 전달되는 응답을 더 이상 막지 않습니다.
- 로딩 단계가 8% → 18% → 46% → 90% → 94% → 97% → 100%로 바뀌며 현재 작업 설명도 함께 표시됩니다.
- 양 배치, 돌 배치, 남부 예루샬라임 주택과 골목 생성, 그래픽 준비, 실제 첫 두 프레임이 끝날 때까지 로딩 화면이 유지됩니다.
- 그래픽 준비 응답이 늦어져도 모바일에서는 제한 시간 뒤 첫 화면으로 계속 진행합니다.
- 성 안에 들어갈 때마다 큰길 시민 1명과 골목 시민 1명은 항상 등장합니다. 나머지 두 시민은 각각 무작위 집에서 나올 수도 있고 이번 입성에는 나타나지 않을 수도 있습니다.
- 성에서 멀리 떨어지면 시민 이동·충돌 계산을 중단하고, 성 안에서도 실제 등장한 시민에게만 계산을 수행합니다.
